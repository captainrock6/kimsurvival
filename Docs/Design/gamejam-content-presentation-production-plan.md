# 《김씨 생존기: 무인도》 게임잼 콘텐츠·프레젠테이션 제작 계획

> 기준: 2026-08-28 O8-H1 중단 직후 저장소·Forge 원장·런타임 화면 점검
>
> 목적: 기능 알파를 게임잼 제출 가능한 30분 버티컬 슬라이스로 끌어올리기 위한 콘텐츠, 아트, 애니메이션, 스토리, 엔딩 범위와 제작 순서를 고정한다.

## 1. 결론

O8-H1 30분 자연 플레이테스트는 지금 계속하는 순서가 아니다. 현재 빌드는 7지역, 유한 수색, 다층 캠프, 세 탈출 경로, 행동 기반 엔딩 판정 같은 **시스템 골격**은 강하지만, 플레이어가 실제 게임으로 받아들이는 스토리·화면·동작·소리·결말 표현은 제출 후보 수준에 도달하지 않았다.

다음 단계는 밸런스 수치 조정보다 **O9 콘텐츠·프레젠테이션 알파**다. O9에서는 5~10분 첫 루프를 최종형에 가까운 화면과 동작으로 완성한다. 30분 자연 플레이는 일곱 지역, 세 탈출 경로, 최소 엔딩 묶음이 실제 자산과 함께 연결된 O10 콘텐츠 베타 뒤에 재개한다.

## 3. 게임잼 제출 콘텐츠 고정 범위

### 3.1 반드시 완성할 것

#### 스토리와 콘텐츠

- 조난 원인, 김씨의 즉시 목표, 코미디의 기준을 한 페이지 시놉시스로 확정한다. 조난 원인은 아직 사용자 결정 전이므로 임의 확정하지 않는다.
- 30~45초 이내, 언제든 스킵 가능한 3~5컷 도입을 만든다.
- 첫 귀환, 첫 제작/연구, 첫 방 증축, 첫 탈출 프로젝트 발견에 짧은 상황 비트를 둔다.
- 일곱 지역 첫 진입에는 위치의 성격, 위험, 다음 단서를 한두 문장으로 소개한다.
- 설명 문구는 규칙과 원인을 우선하고 코미디는 그 뒤에 붙인다.

#### 월드와 오브젝트 아트

- 지붕 있는 1층·2층·지하가 한 화면 계통으로 이어지는 캠프 세트를 완성한다.
- 해변, 숲, 얕은 바다, 바위 해안, 동굴, 난파선, 폐중계소 7지역을 각각 독립 레이어로 만든다.
- 풀숲, 바위틈, 표류물 더미, 나무 구멍, 난파선 수납함, 폐시설 캐비닛을 `미수색/부분 잔류/고갈` 상태로 제공한다.
- 모닥불, 작업대, 빗물받이, 침대, 소파, 지도/계획대, 앨범, 사다리/해치와 3개 탈출 설비를 통일된 실루엣으로 만든다.
- 뗏목·대형 연기·무전 설비는 blueprint, 건설, 진행, 완료가 월드 외형으로 구분돼야 한다.
- 벌레, 야생동물, 위험 식물, 질병을 고어 없이 예고·노출·피해·완화 상태로 표현한다.

#### 김씨 애니메이션

최소 클립은 다음 8개다. 좌우는 별도 제작 대신 안전한 sprite flip을 사용한다.

1. `idle`: 4~6프레임 loop
2. `walk`: 8프레임 loop, 발 미끄러짐 없음
3. `search`: 6~8프레임, 수색물에 손이 닿는 commit frame
4. `facility-use`: 제작·건설·지도 사용 공통 6프레임
5. `ladder`: 6프레임 loop, 손발 간격 고정
6. `swim`: 6~8프레임 loop와 입수/출수 짧은 전환
7. `hurt-sick`: 피격·질병·탈진을 구분하는 짧은 반응
8. `rest-eat`: 침대·소파·식사 회복 피드백

O9 첫 루프 게이트에는 idle, walk, search, facility-use, ladder를 먼저 연결하고, O10에서 swim, hurt-sick, rest-eat를 완료한다.

#### UI

- 타이틀/시작/설정/크레딧/종료
- 생존 HUD와 상태 이상
- 근접 상호작용 표식과 compact prompt
- 설비 팝업, 연구·제작, 건설·재배치, 방 증축
- 7지역 수집 지도와 순차 해금/잔량/위험 표시
- 발견물 트레이와 4→6→8→10칸 가방
- 탈출 프로젝트 단계·핵심 부품·불가능 이유
- 3~5컷 엔딩과 생존 앨범
- 모든 본문은 TMP/현지화 문자열로 두고 래스터에 굽지 않는다.

#### 아이템 아이콘

- 일반 자원 12종: 나무, 표류물, 식량, 천, 섬유, 약재, 돌, 금속, 전선, 연료, 화학 재료, 전자 부품
- 보호 부품 5종: 돛천, 부싯돌, 망가진 무전 송수신기, 망가진 전자기판, 트랜지스터
- 도구 2종: 돌도끼, 밧줄
- 설비·위험·치료·잠금·완료 상태 아이콘은 공통 표식 세트와 같은 선 굵기와 색 체계를 쓴다.

#### 엔딩

게임잼 필수 완성 엔딩은 5개다.

- `ending.escape.raft.open-water`
- `ending.escape.smoke.seen-from-afar`
- `ending.escape.radio.clear-signal`
- `ending.gamejam.stay.natural-kim`
- `ending.gamejam.stay.island-engineer`

반복 플레이를 보여 주는 목표 변형은 3개다.

- 코믹 2종: `ending.comic.smoke.island-barbecue`, `ending.comic.radio.island-dj`
- 희귀 1종: `ending.rare.raft.current-reader`

다섯 core ending은 각각 3개의 고유 panel beat를 가진다. 세 변형은 core sequence의 1~2개 패널을 교체하는 방식으로 제작량을 제어한다. 수영, 기계, 건설, 생존·채집 우세를 보여 주는 재사용 modifier panel 4종을 추가해 최종 결과를 3~5컷으로 조립한다. 나머지 13개 ending ID는 앨범의 제목·실루엣·힌트와 데이터 계약을 유지하되 완성 컷신은 정식 버전으로 미룬다.

#### 오디오

- 환경 loop 4종: 캠프/해안, 숲, 동굴, 폐시설
- 기능 SFX 약 20종: 걷기, 상호작용, 뒤지기, 발견, 담기, 교체, 제작, 건설, 연구, 회복, 위험 예고, 부상, 질병, 치료, 사다리, 수영, 탈출 단계, 성공, 실패, UI 이동/확정
- BGM 2종: 캠프·수색 공용 저강도, 탈출·엔딩용 짧은 테마
- 엔딩 전환과 코믹 punchline sting 2종
- 더빙과 7지역별 완전 고유 음악은 제외한다.

### 3.2 목표 범위

- 세 변형 엔딩과 행동 modifier panel 4종
- 위험별 추가 김씨 reaction pose
- 지역별 전용 환경음 variation
- 앨범 미발견 카드의 개별 실루엣

목표 범위가 일정에 영향을 주면 필수 5엔딩과 첫 루프 가독성을 우선한다.

### 3.3 게임잼에서 제외

- 21개 엔딩 전부의 고유 3~5컷 제작
- 조명탄·고지대 중계소의 플레이 가능 구현과 최종 설비 아트
- 음성 더빙, 완전한 립싱크, 장편 대화 분기
- 지역별 완전 고유 BGM과 영화식 장면 전환
- Steamworks 업적·클라우드·스토어 업로드
- 상점, 전투 HUD, 캐릭터 시트 화면 같은 현재 설계에 없는 자동 발견 항목

## 4. 아트 제작 원칙

- 현재 후보는 서로 화풍이 다르다. 사실적인 지역 배경, 잉크 선이 강한 김씨, 모바일풍 광택 UI를 그대로 섞지 않는다.
- 먼저 한 장의 style benchmark에서 `김씨 + 캠프 + 해변 + HUD + 수색물`을 같은 화면에 합성해 선 굵기, 명암, 채도, 텍스처 밀도와 캐릭터 대비를 잠근다.
- 최종 방향은 기존의 따뜻한 열대색과 코믹한 생활인 김씨를 유지하되, 배경 세부는 한 단계 단순화하고 UI의 광택과 장식을 줄여 PC 횡스크롤 화면을 가리지 않게 한다.
- contact sheet를 런타임에 그대로 넣지 않는다. 배경은 지역별 레이어, UI는 9-slice/SVG/engine-native component, 캐릭터는 프레임별 true-alpha sprite, 오브젝트는 상태별 분리 소스로 납품한다.
- 사용자 채택 전 `review` 후보를 최종 자산으로 간주하지 않는다. 채택된 자산만 package 후 런타임에 연결한다.
- 제3자 게임은 공간 경험과 추상적 정보 원칙만 참고하고 고유 레이아웃, 아이콘, 캐릭터, 문구, 건물 형태를 복제하지 않는다.

## 5. 제작 단계

### O9 — 콘텐츠·프레젠테이션 알파

목표는 **처음 5~10분이 실제 게임처럼 보이고 이해되는가**를 검증하는 것이다.

작업:

1. 시놉시스, 도입 3~5컷, 7지역 소개, 5 core ending beat와 3 variant 교체 beat를 문서로 잠근다.
2. style benchmark와 UI component 규칙을 채택한다.
3. 타이틀·도입·HUD·캠프 팝업·지도·수색 트레이의 final-direction skin을 만든다.
4. 김씨 idle/walk/search/facility-use/ladder를 실제 clip으로 연결한다.
5. 캠프 1층·지붕, 해변, 숲, 핵심 수색물과 아이템 아이콘을 production asset으로 교체한다.
6. 대표 엔딩 한 종을 실제 3컷로 미리보기 가능하게 연결한다.
7. 캠프/해안 환경음과 첫 루프 필수 SFX를 연결한다.

완료 게이트:

- 새 플레이어가 타이틀→도입→캠프→지도→해변/숲→뒤지기→선별→귀환→첫 투자까지 10분 안에 진행한다.
- 그 경로에서 임시 네모, 도식형 사람, contact sheet, 개발자용 설명 패널이 주 표현으로 보이지 않는다.
- 김씨 발이 지면에 붙고, 이동·수색·설비 사용이 서로 다른 동작으로 읽힌다.
- 1280×800 KO/EN에서 UI가 김씨, 상호작용 대상, 발견물을 동시에 가리지 않는다.
- 대표 엔딩 preview가 결과·원인·후일담을 그림으로 전달한다.

이 게이트 뒤에는 30분 테스트가 아니라 **5~10분 first-loop 사용자 테스트**만 진행한다.

### O10 — 30분 콘텐츠 베타

작업:

- 나머지 5지역과 모든 수색물 상태를 연결한다.
- 2층·지하, 침대·소파, 사다리·해치, 위험 표현, 3개 탈출 설비의 모든 단계를 연결한다.
- 19개 필수 아이템 아이콘과 김씨 swim/hurt-sick/rest-eat를 연결한다.
- 5 core ending, 필수 오디오와 KO/EN 서사 문안을 완성한다.
- 세 경로를 각각 자연 플레이로 완주 가능한 자원 예산으로 동결한다.

완료 게이트:

- 7지역이 그림·음향·위험·주요 자원으로 구분된다.
- 뗏목·연기·무전 중 각 경로를 독립 seed에서 25~35분 안에 완주한다.
- 필수 5엔딩이 실제 3컷이고 앨범에서 재생된다.
- 이 시점부터 30분 자연 플레이테스트를 재개한다.

### O11 — 반복 플레이·폴리시

- 코믹 2종·희귀 1종 교체 패널과 행동 modifier 4종을 연결한다.
- 경고·치료·탈출·엔딩 오디오, 화면 전환, 카메라, hit feedback을 다듬는다.
- qps-long, 키보드·마우스, 물리 게임패드, 1280×800·1920×1080을 검증한다.
- 첫 사용자 KO 3명·EN 3명으로 설명자 없는 세션을 진행한다.

### O12 — 게임잼 RC

- P0/P1만 수정하고 기능·콘텐츠를 동결한다.
- 30분 완주, 굶주림 실패, 세 탈출, 두 장기 체류, 엔딩 앨범, 재시작을 검증한다.
- Release 빌드, 크레딧·라이선스, 게임잼 규정 준수, 실행 파일·README·스크린샷을 패키징한다.

## 6. 한 달 일정 기준

| 기간 | 목표 |
|---|---|
| 1주차 | O9 콘텐츠 잠금, style benchmark, UI 방향, 김씨 core animation, 캠프·해변·숲 |
| 2주차 | 7지역·수색물·캠프 3층·아이템·위험·탈출 설비 production asset과 통합 |
| 3주차 | 5 core ending, 오디오, 30분 콘텐츠 베타와 세 탈출 경로 완주 |
| 4주차 | 3 variant/modifier, first-user QA, 게임패드·해상도·현지화·Release 제출 패키지 |

가장 큰 일정 위험은 기능 코드가 아니라 **아트 방향을 늦게 바꾸는 것**과 **contact sheet를 엔진용 자산으로 잘못 취급하는 것**이다. O9 첫 이틀 안에 style benchmark와 김씨 비율을 잠그지 못하면 변형 엔딩과 추가 reaction을 먼저 줄이고 필수 5엔딩과 첫 루프를 보호한다.

## 7. 다음 제작 단계의 의사결정 게이트

O9 실제 제작을 시작하기 전에 사용자에게 필요한 결정은 두 가지다.

1. 조난 원인과 도입 톤: 현실적인 사고, 폭풍 표류, 정체불명 섬 중 어느 방향인지
2. style benchmark: 기존 김씨의 잉크 선을 기준으로 배경을 단순화할지, 배경의 회화성을 기준으로 김씨를 다시 정리할지

나머지 UI 정보 구조, 애니메이션 클립 목록, 게임잼 엔딩 최소 묶음은 이 문서 기준으로 진행 가능하다.

## 8. 재개 테스트 순서

1. O9: 5~10분 first-loop presentation test
2. O10: 30분 natural completion test, 뗏목·연기·무전 각 1회
3. O11: 반복 플레이와 엔딩 변형 발견성 test
4. O12: 최종 Release 호환성·제출 패키지 test

O8 기능 체크리스트는 폐기하지 않는다. O10 30분 테스트 체크리스트에 포함해 새 자산 연결이 기존 시스템 계약을 깨지 않았는지 함께 확인한다.

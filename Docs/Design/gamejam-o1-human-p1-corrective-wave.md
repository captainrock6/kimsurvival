## 문제 정의

O1에서 내부 상태기계와 탈출 가능성은 확인됐지만, 플레이어는 재료와 행동의 의미를 읽지 못했고 21분 50초에 테스트를 중단했다. 자동 계약의 `DONE`은 실행 가능성과 데이터 보존을 증명했을 뿐, 사람이 화면을 보고 이해하는 제품 조건을 증명하지 못했다.

| ID | 증상 | 제출 영향 | 교정 원칙 |
|---|---|---|---|
| H-001 | HUD·팝업·월드 안내가 과밀하고 임시 블록처럼 보인다. | 첫 10분 핵심 루프 이해 실패 | 지속 HUD, 상황 안내, 행동 팝업을 분리하고 한 시점의 주 행동을 하나만 강조한다. |
| H-002 | 같은 재료가 수색 결과·가방·베이스에서 다른 이름과 표현으로 보인다. | 수집·투자 판단 불가 | stable resource ID 하나에 KO/EN 이름·아이콘·색·단위를 한 번만 매핑해 모든 표면이 공유한다. |
| H-003 | 2층·지하실 증축의 목적·비용·잠금·완료 여부를 알 수 없다. | 다층 캠프 기능 사실상 미사용 | 확장별 결과, 비용, 부족분, 상태와 다음 추천을 행동 전후 같은 카드에서 보여준다. |
| H-004 | 김씨가 지면 위에 떠 있고 대기·걷기 애니메이션이 없다. | 기본 이동의 완성도와 공간 감각 훼손 | 발 기준 anchor와 collider를 맞추고 지상 idle/walk/facing 상태를 명시한다. |
| H-005 | 제작된 리소스가 의미 구분에 기여하지 않는다. | 시각 품질·신뢰도 저하 | `engine_ready` 또는 이미 채택된 리소스만 실제 UI·캐릭터·설비 의미에 연결한다. `review`는 임의 사용하지 않는다. |

## 구현 레인

### 1. UI·재료 의미 레인

- canonical resource presentation을 stable ID 기준으로 단일화한다.
- 수색 tray, 가방 슬롯, 베이스 보유량, 제작 비용이 동일한 이름·아이콘·단위를 사용한다.
- 1280×800에서 지속 HUD는 생존 상태·목표·핵심 보유량만 남기고 조작 설명은 상황성 도움으로 내린다.
- 한국어를 기본으로 하고 영어와 장문 pseudo locale가 같은 의미 구조를 사용한다.

### 2. 증축 UX 레인

- 2층, 지하실, 측면 확장을 서로 다른 결과 문장과 실루엣/아이콘으로 구분한다.
- `LOCKED`, `SHORT`, `READY`, `DONE`을 색상만이 아니라 상태 문구·아이콘·행동 가능 여부로 표현한다.
- 비용은 보유/필요와 부족분을 함께 표시하고, 완료 뒤 열린 설치 공간과 이동 연결을 즉시 확인시킨다.

### 3. 캐릭터 표현 레인

- 김씨의 발 anchor가 캠프와 수색 지면에 일치하도록 pivot·offset·collider 관계를 고정한다.
- 지상 `idle`, `walk`, 좌우 facing 전환을 구현하고 이동 중 hover/bob을 제거한다.
- 수영은 별도 상태로 보존하며 `review` 수영 애니메이션을 임의 채택하지 않는다.

### 4. 통합·QA 레인

- 기존 저장·수색 원자성·세 탈출·엔딩 회귀를 보존한다.
- KO/EN 1280×800에서 캠프, 수색 tray, 가방, 증축 카드와 이동 캐릭터를 캡처해 사람이 직접 검토한다.
- 새 후보는 H-001~H-005가 모두 수정 증거와 연결된 뒤에만 만든다.

## 완료 조건

1. 같은 재료가 수색 결과, 가방, 베이스 보유량, 제작 비용에서 같은 이름·아이콘으로 보인다.
2. 처음 보는 사람이 외부 설명 없이 현재 목표와 다음 행동을 한 화면에서 말할 수 있다.
3. 2층과 지하실 각각의 목적, 비용, 잠금 이유, 완료 상태와 열린 공간을 설명할 수 있다.
4. 김씨의 발이 평지에 붙고 대기·걷기·방향 전환이 시각적으로 구분된다.
5. `review` 아트의 무단 채택 없이 승인 상태 리소스의 실제 런타임 사용 경로를 증명한다.
6. compile 0 errors, 핵심 자동 회귀 GREEN, 1280×800 시각 검토 후 새 Release 후보를 동결한다.
7. 새 후보에서 O2 소유자 재테스트를 먼저 통과한 뒤 KO 3명·EN 3명 첫 사용자 세션을 시작한다.

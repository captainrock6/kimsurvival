이 문서는 처음 보는 사람의 20분 외부 플레이테스트에 넣을 후보 빌드의 수치와 Wave 5 구현·QA 게이트를 함께 잠근다. `현재값`은 기준점 런타임에 실제로 들어 있는 값이고, `v0.2`는 외부 시험 전에 구현할 값이다. `허용 범위`는 후보 빌드가 임의로 달라도 된다는 뜻이 아니라, 유효한 외부 6세션 뒤 한 번에 한 축을 조정할 수 있는 최대 경계다.

사람이 수행한 외부 플레이테스트 결과는 아직 없다. 통합 자동 경로의 PASS는 기능·산술 재현 증거이며 첫 경험 이해도나 인간 성공률을 대신하지 않는다.

## 1. Wave 5 잠금 결정

1. 외부 시험 전 수치 변경은 시작 식량 `1→0`, 시작 허기 `75→70`, 하루 종료 허기 소모 `25→35` 세 개만 즉시 구현한다.
2. 노드 수·획득량, 4칸/중첩 2, 제작·연구·건설·구조 비용, 육상·수영 비용은 현재값이 v0.2와 같으므로 잠근다.
3. 외부 6세션은 정확히 같은 후보 빌드로 `ko 3명/en 3명`을 관찰한다. 튜토리얼과 공략 힌트는 제공하지 않고 수기 기록만 사용한다.
4. 발견성·문구·레이아웃이 이정표를 막은 데이터로 자원 비용을 바꾸지 않는다. 먼저 원인을 수정하고 새 6인 코호트를 실행한다.
5. 배경 패키지 도달성, qps-long 10/10, Addressables 안정성, ko/en 자연 루프가 모두 통과해야 외부 시험 후보를 `READY`로 판정한다. 물리 게임패드는 별도 `UNVERIFIED` 상태를 유지할 수 있지만 PASS로 대체 보고하지 않는다.

## 3. Day 1~3 플레이테스트 진행표

아래 `평균 목표 경로`는 실측 평균이 아니라 20분 안에 성장 단계를 모두 보여 주는 설계 기준이다. 참가자에게 이 순서나 자원 조합을 알려 주지 않는다.

| 일자 | 목표 원정 유입 | 캠프 소모·성장 | 종료 목표 | 주요 실패 원인 |
|---|---|---|---|---|
| Day 1 | `W2/D4/F2`, 8개·4칸 | 작업대 `W2/D1`, 밧줄 연구 `D1`, 밧줄 제작 `W1/D1`, 식량 1 사용 | `W1/S1/F1/D1`, H65, 다음 날 E 약75 | 귀환 미발견, 수영 회피로 D 부족, 가방 초과 선택 정지 |
| Day 2 | `W4/S2/D2`, 8개·4칸 | 도끼 연구 `S1/D1`·제작 `W1/S1`, 모닥불 `W2/S1`, 신호 1 `W2/D2` | `W0/S0/F1/D0`, H30, 다음 날 E 약78.2 | 연구/제작 인과 혼동, 잘못된 소비 순서, 과도한 수영으로 탈진 |
| Day 3 | 도끼 W 노드 `W3`+`D2/F2`, 7개·4칸 | 신호 2 `W2/D2` | 즉시 구조, 예시 E51.2/L62.5 | 신호 앵커·밧줄 조건 미발견, 20분 timeout, 3일 정산 기한 실패 |

Day 1 예시 비용은 육상 이동 40초 `E7.2/L30`, 수영 이동 12초 `E7.8/L13.8`, 육상 채집 2회 `E12`, 수영 수색 2회 `E18`으로 합계 `E45/L43.8`다. 귀환 `E55/L56.2`에서 기본 회복을 받아 Day 2를 E75로 시작한다.

Day 2 예시는 육상 이동 60초와 채집 4회로 `E34.8/L45`를 쓰고 E40.2로 귀환한 뒤 모닥불 회복으로 E78.2가 된다. Day 3 예시는 육상 이동 50초와 채집 3회로 `E27/L37.5`를 써 `E51.2/L62.5`에 구조한다.

### 3.1 숙련 최소 성공: 2회 원정

1. Day 1에 `W2/D4/F2`를 가져와 작업대·밧줄 연구·밧줄 제작을 완료하고 식량 1을 먹는다.
2. 창고는 `W1/S1/F1/D1`, H65가 된다.
3. Day 2에 후반 노드에서 `W4/D4`를 가져와 신호 1·2단계에 `W4/D4`를 연속 지불한다.
4. `W1/S1/F1/D1`을 남기고 Day 2에 구조된다.

판정: 한 원정 성공은 불가능하고 2회 최단 성공은 가능하다.

### 3.2 욕심 실패: Day 2 수영 탈진

1. Day 1에 육상 4개와 수영 2개 노드를 모두 건드리되 초과분을 버린다.
2. 육상 이동 60초 `E10.8/L45`, 수영 이동 34초 `E22.1/L39.1`, 육상 채집 4회 E24, 수영 수색 2회 E18로 `E74.9/L84.1`을 쓴다.
3. E25.1에 귀환해 기본 회복 뒤 Day 2를 E45.1로 시작한다.
4. Day 2에 수영 이동 42초 `E27.3/L48.3`와 수영 수색 2회 E18을 반복하면 총 E45.3을 써 L이 남은 상태에서 탈진한다.

판정: 안전한 선택은 2~3회 원정에 성공하지만, 가방에 담지 못할 노드까지 반복 수색하면 일몰 전에도 실패한다. 별도로 Day 3 정산까지 신호 2가 미완성이면 기한 실패한다.

### 4.2 튜토리얼 없이 볼 발견성

| 가방 만석 | 교체/포기 뒤 목적 자원을 선택 | 선택 의미를 몰라 진행 중단 |
| 귀환 | 자원을 창고로 옮기고 새 행동이 열린 것을 확인 | 가방과 창고를 같은 공간으로 오해 |
| 작업대 | 연구→제작과 설비 설치의 차이를 추론 | 비용은 있는데 선행 조건을 역순으로 반복 |
| 배치 | 유효/무효 피드백으로 위치를 고르고 김씨가 다가가 사용 | 설치를 장식으로 보거나 무효 사유를 읽지 못함 |
| 해안 | 입수→수상 수색→출수, E/L 추가 소모를 인지 | 물을 벽으로 오해하거나 복귀 방법을 잃음 |
| 신호 앵커 | 고정 위치와 2단계 진행을 목표로 연결 | 일반 자유 배치 설비로 오해, 1/2와 2/2 혼동 |
| 결말 | 구조·탈진·기한의 직접 원인을 설명 | 실제 상태와 반대 원인을 답함 |

진행자는 자원 비용, 작업대→밧줄 순서, 물 위치, 신호 앵커, 위험 수치를 먼저 말하지 않는다. H2/H3 도움 뒤 이정표는 assisted로 기록하고 자연 달성 합격선에서 제외한다.

## 8. 외부 6세션 변경·유지·보류 임계값

### 8.1 집계 유효성

전체 밸런스 판정은 같은 후보 커밋·바이너리의 유효 6세션, ko 3/en 3, 각 20분, H0/H1 자연 달성만으로 한다. H2/H3 뒤 달성, 잘못된 빌드·locale, P0 중단, 참가자 중단은 원인만 남기고 비율에서 제외하며 같은 locale 참가자로 보충한다. 6명보다 적은 결과를 백분율로 환산하지 않는다.

## 9. 기록·인계 계약

- 외부 실행과 수기 양식은 `wave4-external-playtest-protocol.md`를 그대로 사용한다. 게임 내 텔레메트리, 음성·영상, 이름·연락처·Steam 계정은 수집하지 않는다.
- 결과 보고에는 각 게이트의 전체 `n/6`, locale별 `n/3`, 완료 시간 중앙값, 구조 결과, 도움 등급, E/H/L, 공통 원인만 적는다. 사람이 하지 않은 결과를 채우지 않는다.
- 밸런스 변경 제안에는 `관찰→임계값→선택한 한 값→기대 효과→재검증`을 모두 기록한다.
- qps-long은 비출하 QA 로케일이다. 향후 JA/ZH/ES 지원 준비를 검사하지만 실제 번역이나 공식 영문 제목 결정을 대신하지 않는다.
- Wave 5 기획 산출물은 이 문서이며, 공유 Forge JSON·런타임·씬·아트·QA·Addressables의 현재 상태를 변경하지 않는다.

# Wave 7 가방 용량 업그레이드 계약

## 목표

플레이어가 구조 신호대에 곧바로 투자할지, 다음 수색의 운반 효율을 높일지 선택하게 한다. 업그레이드는 생존 루프를 넓히되 기존의 가방 교체 선택을 없애지 않는 작은 영구 성장이어야 한다.

## 확정 규칙

| 항목 | 계약 |
| --- | --- |
| 기본 용량 | 4칸 |
| 업그레이드 용량 | 6칸 |
| 칸당 중첩 한도 | 2개, 업그레이드 전후 동일 |
| 해금 장소 | 베이스캠프의 건설 완료된 작업대 |
| 비용 | 나무 2 + 표류물 1 |
| 횟수 | 한 게임에서 1회 |
| 지속 | 날짜와 원정을 넘어 유지, 새 게임에서 4칸으로 초기화 |
| 성격 | 선택 성장. 구조 신호대 완성의 필수 조건이 아님 |

밧줄은 현재 수량 자원이 아닌 영구 도구이며 구조 신호대 2단계에도 필요하므로 비용에 넣지 않는다. 이번 Wave에서는 중첩 한도 증가, 무게, 여러 단계, 세이브·로드를 추가하지 않는다.

## 플레이 흐름과 피드백

1. 작업대가 없으면 업그레이드 행동은 잠겨 있고 `작업대 필요 / Workbench Required`를 표시한다.
2. 작업대가 있으면 `가방 확장 4→6 · 나무 2 · 표류물 1`과 영어 동등 문구를 표시한다.
3. 자원이 부족하면 부족한 항목과 수량을 보이고, 어떤 자원도 차감하지 않는다.
4. 성공하면 비용을 정확히 한 번 차감하고 5·6번 슬롯을 즉시 활성화한다.
5. 완료 뒤에는 재구매할 수 없으며 `가방 확장 완료 6칸 / Bag Upgrade Complete · 6 Slots`를 표시한다.
6. 업그레이드 전에도 잠긴 두 칸 또는 `4/6` 상태가 보여 다음 성장 목표를 이해할 수 있어야 한다.

모든 플레이어 문구는 한국어를 기본으로 하고 영어를 지원하며, 문자열 키와 매개변수 기반으로 다른 언어를 추가할 수 있어야 한다. 래스터 아트에는 본문 문구를 굽지 않는다.

## 수용 조건

- 새 게임은 4칸으로 시작하고 기존 `가방 가득 참 → 교체/포기` 선택이 최소 한 번 재현된다.
- 작업대와 정확한 비용을 갖췄을 때만 6칸으로 확장되며, 실패·취소·반복 입력은 자원을 소모하지 않는다.
- 업그레이드 뒤 5·6번 슬롯에서 획득, 중첩, 교체, 폐기, 귀환 이전이 1~4번 슬롯과 동일하게 동작한다.
- 키보드·마우스와 게임패드가 활성 슬롯 전체를 조작하며, 잠긴 슬롯은 업그레이드 전에 선택되지 않는다.
- 1280×800과 1920×1080에서 4칸·6칸 가방, 비용, 완료 상태가 겹치거나 잘리지 않는다.
- 업그레이드를 선택한 자연스러운 3일 플레이에서도 구조 성공 경로가 존재하고, 기존 구조 신호대·돌도끼·장벽·배치·수영 회귀 테스트가 통과한다.
- 실제 게임패드와 Steam 검증은 장치 또는 배포 권한이 없으면 `UNVERIFIED` 또는 `NOT_READY`로 유지한다.

## 병렬 작업 경계

- 기획·밸런스: 비용과 3일 경로 검증, 문서와 Forge 상태만 담당한다.
- 아트·UI: 가방 확장 전후 시각 후보를 제작하고 검토 상태로 전달한다. 사용자 채택 전 런타임에 넣지 않는다.
- Unity 시스템: 상태, 비용, 동적 슬롯 UI, 입력, 현지화와 자동 테스트를 구현한다. 새 아트는 채택 전 사용하지 않는다.
- QA·Steam 준비: 독립 회귀 러너와 증거를 담당하고 런타임 로직을 수정하지 않는다.

## 변경 통제

`4→6`, 중첩 2, 작업대 1회 업그레이드는 이번 Wave의 고정 계약이다. `나무 2 + 표류물 1`이 구조 성공을 막는다는 재현 가능한 증거가 나올 때만 기획 작업이 대체 비용을 제안할 수 있으며, Unity·QA 작업에 먼저 알리고 통합 시 한 번에 반영한다.

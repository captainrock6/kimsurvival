# Wave 8 첫 사용자 20분 플레이테스트 실행 패키지

> 상태: `READY_TO_SCHEDULE / NOT_EXECUTED`
> 설계 기준점: Wave 12 `origin/master 86b6db8d5bc628aa7cb9cdb0d3e59539b6633c91`
> 대상: 현재 5일 구조 신호대 탈출 수직 슬라이스, Windows 키보드·마우스 빌드
> 표본: 첫 사용자 6명(`ko` 3명, `en` 3명)
> 공식 영문 게임 제목: `TBD` — 테스트 중 임의 영문 제목을 만들지 않는다.

이 문서는 `decision.wave4.external-playtest-manual-naive`와 `decision.wave4.playtest-severity-routing`을 계승해 실제 진행자가 바로 인쇄·실행할 수 있게 만든 Wave 8 정본이다. 이번 6인 코호트에서는 이 문서가 `wave4-external-playtest-protocol.md`의 실행 세부보다 우선한다. 특히 **구체적 해결 힌트는 전면 금지**하며, 조기 결말 뒤에도 관찰 창은 정확히 20:00까지 유지한다. 이전 문서는 역사적 근거로 보존한다.

이 패키지는 참가자를 섭외하거나 메시지를 보내는 문서가 아니다. 아직 사람이 수행한 결과가 없으며, 아래 빈칸과 표는 실행 전 예상값이나 가상 결과로 채우지 않는다.

## 1. 검증 질문과 고정 조건

핵심 질문은 다음 하나다.

> 설명 없이 처음 접한 사용자가 `채집 → 귀환 → 제작/연구 → 배치·접근 사용 → 수영 → 구조 또는 실패`를 자연스럽게 이해하고, 20분 안에 5일 루프의 결말까지 도달하는가?

세션 전 다음 조건을 모두 고정한다.

| 항목 | 고정 계약 |
|---|---|
| 참가자 | 게임을 처음 보는 유효 참가자 6명. `ko`를 편하게 읽는 3명과 `en`을 편하게 읽는 3명 |
| 익명 코드 | 실행 순서대로 `K01, E01, K02, E02, K03, E03`. 이름·나이·성별·연락처를 적지 않음 |
| 빌드 | 6명 모두 동일한 Windows x64 실행 파일, 동일 commit과 EXE SHA-256 |
| 화면·입력 | 1280×800, 키보드·마우스, 동일 장비 설정. 물리 게임패드는 별도 `UNVERIFIED` 세션이며 이 6명에 섞지 않음 |
| 언어 | `Kxx=ko`, `Exx=en`; 세션 중 언어 변경 금지 |
| 관찰 시간 | 참가자별 게임 입력 시작부터 정확히 20:00. 재시작·재플레이 없음 |
| 도움 | 조작법, 목표, 비용, 정답, 위치, 행동 종류, 순서, 위험을 알려주는 해결 힌트 금지 |
| 기록 | 종이 또는 로컬 수기 표만 사용. 게임 내 텔레메트리·분석 SDK·화면 녹화·음성·영상 없음 |
| 변경 동결 | 유효 6세션 집계와 게이트 판정 전까지 자원·비용·노드·가방·E/H/L 수치를 바꾸지 않음 |

`ko/en`의 언어 편안함과 첫 사용자 여부는 `예/아니오`만 확인한다. 실제 언어 능력 점수나 인구통계는 수집하지 않는다.

## 3. 참가자별 일정

준비와 사후 질문은 20분 게임 관찰 창 밖에서 수행한다.

| 구간 | 시간 | 실행 |
|---|---:|---|
| 준비 | 약 3분 | 첫 사용자·locale 편안함·익명 기록 동의만 확인하고 시작 문구를 읽음 |
| 관찰 | 정확히 20:00 | 입력 시작과 동시에 타이머 시작. 말없이 관찰·수기 기록. 15:00에 남은 시간만 알림 |
| 사후 이해도 | 약 5분 | 게임 입력을 멈춘 뒤 고정 5문항을 순서대로 질문하고 자발 답변만 채점 |
| 초기화 | 약 2분 | 기록지 유효성 확인, 게임 종료, 다음 locale의 새 게임 준비 |

조기 결말이 나오면 `END` 시각과 결과를 기록하고 참가자의 입력을 멈춘다. 재시작하거나 다시 플레이하지 않고 결과 화면을 유지한 채 20:00까지 기다린 뒤 사후 질문으로 이동한다. 20:00에 결말이 없으면 즉시 입력을 멈추고 `TIMEOUT`으로 기록한다.

## 4. 진행자 고정 스크립트

### 4.1 시작 문구

`ko`:

> 지금부터 정확히 20분 동안 게임을 플레이합니다. 여러분이 아니라 게임을 시험하는 자리입니다. 조작법이나 해결 방법은 설명하지 않겠습니다. 화면에서 이해한 대로 진행해 주세요. 이름이나 연락처는 기록하지 않고 익명 수기 메모만 남깁니다. 언제든 중단을 요청할 수 있습니다.

`en`:

> You will play for exactly 20 minutes. We are testing the game, not you. I will not explain the controls or how to solve it. Please continue based on what you understand from the screen. We will keep only anonymous handwritten notes, with no name or contact details. You may ask to stop at any time.

공식 영문 게임 제목은 말하지 않는다. 필요하면 “this five-day island survival prototype”이라고만 설명한다.

### 4.2 허용 응답

| 상황 | `ko` | `en` |
|---|---|---|
| “뭘 해야 하죠?” | “화면에서 이해한 대로 계속해 주세요.” | “Please continue based on what you understand from the screen.” |
| 문구·아이콘 의미 질문 | “지금은 설명하지 않겠습니다. 화면에서 이해한 대로 진행해 주세요.” | “I will not explain it right now. Please continue based on what you understand from the screen.” |
| 15:00 | “5분 남았습니다.” | “Five minutes remain.” |
| 조기 결말 | “결과를 기록했습니다. 이 화면에서 기다려 주세요.” | “I recorded the result. Please wait on this screen.” |
| 20:00 | “여기서 멈추겠습니다.” | “We will stop here.” |
| 중단 요청 | “알겠습니다. 여기서 중단하겠습니다.” | “Understood. We will stop here.” |

정체 시간과 관계없이 추가 프롬프트는 주지 않는다. 침묵, 생각 소리, 화면에 보이는 문구를 참가자가 읽는 것은 기록하되 유도 질문을 하지 않는다.

### 4.3 금지 행동

진행자는 다음을 하지 않는다.

- 화면·버튼·지도 위치를 가리키거나 마우스·키보드를 대신 조작한다.
- 제작/연구/건설의 행동 종류, 비용, 순서 또는 정답을 말한다.
- 귀환 위치, 수영 노드, 돌도끼 장벽, 작업대, 구조 신호 앵커를 알려준다.
- 가방 업그레이드를 추천하거나 구조 투자를 우선하라고 말한다.
- E/H/L 위험, 남은 날짜, 성공·실패 조건을 화면 밖 설명으로 보충한다.
- “거의 맞았다”, “다른 걸 해보라” 같은 방향성 피드백을 준다.

구체적 힌트가 한 번이라도 제공된 세션은 `HINT_CONTAMINATED`로 무효 처리하고 같은 locale의 새 첫 사용자로 대체한다. 무효 세션의 이정표는 합격선에 포함하지 않는다.

## 5. 핵심 이정표 정의와 합격선

시간은 게임 입력 시작을 `00:00`으로 한 최초 달성 시각이다. `C1`은 기존 정본과 같이 **제작품 하나 생성 또는 연구 하나 해금 중 먼저 일어난 것**이며, 제작과 연구 각각의 시각도 진단란에 따로 적는다.

| 코드 | 이정표와 달성 정의 | 제한 | 전체 합격선 | locale 합격선 |
|---|---|---:|---:|---:|
| G | 나무·돌·식량·표류물 중 하나가 가방에 실제 추가된 첫 채집 | 03:00 이내 | 5/6 이상 | `ko`, `en` 각 2/3 이상 |
| R1 | 귀환 실행 뒤 가방 자원이 캠프 창고로 실제 이전된 첫 귀환 | 06:00 이내 | 5/6 이상 | 각 2/3 이상 |
| C1 | 제작품 하나 생성 또는 연구 하나 해금 | 10:00 이내 | 5/6 이상 | 각 2/3 이상 |
| P1 | 일반 설비가 호환 구역에 확정되어 접근 가능한 첫 유효 설치 | 12:00 이내 | 5/6 이상 | 각 2/3 이상 |
| W1 | 물 진입 → 수상 노드 1개 수색 → 다시 육상 상태 복귀 | 14:00 이내 | 5/6 이상 | 각 2/3 이상 |
| S1 | 전용 앵커에서 구조 신호대 1단계가 실제 반영됨 | 17:00 이내 | 4/6 이상 | 각 1/3 이상 |
| END | 구조 성공·탈진·기한 실패 중 하나가 표시됨 | 20:00 이내 | 5/6 이상 | 각 2/3 이상 |
| RESCUE | 구조 신호대 2단계 완성으로 구조 성공 | 20:00 이내 | **3~4/6** | 각 locale 1명 이상 |
| RDAY | 구조 성공 Day 기록; Day 3 조기 성공 허용, 첫 플레이 목표 Day 4~5 | 성공 세션 | Day 4~5 성공 2회 이상 | locale 강제 분포 없음 |

`TIMEOUT`, 참가자 중단, 크래시 또는 입력 상실은 END가 아니다. END 중앙값 목표는 15:00~20:00이며, 실제 값이 없기 때문에 이 문서에는 중앙값을 미리 적지 않는다.

## 6. Wave 7 선택과 발견성 관찰

이 절의 사건은 진행자가 설명하지 않고 수기로만 기록한다. 합격선과 진단 기준을 분리해 작은 표본의 행동 하나로 즉시 수치를 바꾸지 않는다.

### 6.1 가방 4→6과 구조 신호 투자 경쟁

| 관찰 코드 | 기록할 사건 |
|---|---|
| B4FULL | 4칸 만석 최초 시각·Day, 당시 슬롯 내용, 5번째 획득 시도 여부 |
| BSWAP | 교체 또는 포기 선택과 그 이유를 참가자가 자발적으로 말했는지 |
| BSEEN | 작업대의 4→6 업그레이드 상태·비용을 처음 확인한 시각 |
| BBUY | 업그레이드 구매 여부·시각·Day, 구매 직전 W/D와 신호 단계 |
| BSIGNAL | 신호 투자를 먼저 한 여부·시각·Day, 당시 가방 용량 |
| BORDER | 최초 경제 선택을 `BAG_FIRST / SIGNAL_FIRST / NO_DECISION`으로 분류 |

업그레이드 구매율 자체는 합격/실패가 아니다. `B4FULL`은 4칸 선택 압력이 보이는 진단이며, `BBUY`와 `BSIGNAL`의 순서가 선택 경쟁을 보여준다. 가방 업그레이드를 구매해야만 성공하거나 구매하면 항상 실패하는 동일 원인이 2명 이상에게 재현될 때만 결과 게이트에서 단일 수치 축 검토를 연다.

### 6.2 돌도끼 장벽

| 관찰 코드 | 기록할 사건 |
|---|---|
| AXE_SEE | 녹색 덩굴/나무 장벽을 처음 본 시각과 시도 행동 |
| AXE_INFER | 제작 전에 돌도끼가 장벽 해제 도구라고 추론했는지 |
| AXE_ROPE | 밧줄이 장벽 해제 도구라고 오해했는지 |
| AXE_CLEAR | 돌도끼 보유 뒤 장벽을 실제 제거했는지 |
| AXE_WOOD | 돌도끼의 나무 채집 `+1`을 화면·획득량으로 알아차렸는지 |

돌도끼는 장벽 해제와 나무 채집 `+1`이다. “두 배”로 기록하거나 안내하지 않는다. 밧줄은 구조 신호 2단계의 필수 도구이며 장벽·절벽·구덩이 도구로 해석하지 않는다.

### 6.3 수영 위험

| 관찰 코드 | 기록할 사건 |
|---|---|
| SWIM_ENTER | 첫 입수 시각, 망설임·되돌아섬 여부 |
| SWIM_NODE | 수상 노드 수색 시각과 자원 |
| SWIM_RETURN | 육상 복귀 시각과 복귀 E/L |
| SWIM_RISK | 참가자가 수영의 추가 E/L 소모와 귀환 여유를 자발적으로 말하거나 행동에 반영했는지 |
| SWIM_FAIL | 수영 중 E0, 복귀 실패, 위험을 무시한 반복 진입 여부 |

### 6.4 공간형 캠프

| 관찰 코드 | 기록할 사건 |
|---|---|
| CAMP_INVALID | 일반 설비 무효 위치 시도 횟수와 참가자가 추론한 이유 |
| CAMP_VALID | 모닥불/작업대의 첫 유효 설치 위치와 시각 |
| CAMP_APPROACH | 설치된 일반 설비에 김씨가 직접 다가가 기능을 사용했는지 |
| CAMP_REMOTE | 원거리에서 사용하려 한 횟수 |
| CAMP_ANCHOR | 구조 신호대를 일반 설비처럼 두려 했는지, 전용 앵커를 이해했는지 |
| CAMP_MOVE | 일반 설비를 무비용 재배치했는지와 동선 개선 이유 |

공간형 캠프는 장식이 아니라 김씨의 동선과 기능 사용 공간이다. `CAMP_APPROACH`는 유효 참가자 5/6 이상, locale별 2/3 이상이 직접 접근·사용해야 합격한다. 이 기준이 실패하면 자원 비용보다 배치·거리·상호작용 발견성을 먼저 수정한다.

## 10. 중단·무효·교체 규칙

### 10.1 개인 세션

다음이면 해당 세션을 멈추고 합격선에서 제외한다.

- 참가자가 중단을 요청하거나 익명 기록에 동의하지 않음
- 잘못된 locale·빌드·초기 상태 또는 다른 입력 장치로 시작함
- 크래시, softlock, 입력 단절 또는 표시 장애가 30초를 넘김
- 진행자가 금지된 구체적 힌트를 제공함
- 개인 식별 정보, 음성·영상·화면 또는 게임 내 텔레메트리가 기록됨

앞의 네 경우는 같은 locale의 새 첫 사용자로 대체한다. 개인정보 사고는 오염 기록을 폐기하고 `PRIVACY_STOP` 코드만 남긴 뒤 코호트 전체를 중단한다.

### 10.2 코호트 즉시 중단

- 크래시, 진행 상태 파괴, 영구 softlock, 입력 완전 상실 같은 P0가 한 번이라도 재현됨
- 서로 다른 build commit·EXE SHA·수치가 섞임
- 구체적 힌트 오염이 두 세션에서 발생함
- 개인정보·음성·영상·텔레메트리 기록 사고가 발생함
- 같은 화면·문구·입력 문제가 서로 다른 2명에게서 다음 핵심 이정표를 완전히 차단함
- 첫 3명의 유효 세션 중 아무도 06:00 안에 첫 귀환하지 못함

중단 뒤 수정된 빌드를 사용하면 기존 결과와 섞지 않고 6세션을 처음부터 다시 실행한다.

## 11. 결과 판정과 P0/P1/P2 환류

결정은 다음 순서로 한 번만 내린다. 유효 6세션이 모이기 전에는 수치 판정을 하지 않는다.

| 게이트 | 조건 | 판정과 조치 |
|---|---|---|
| `STOP_P0` | P0, 개인정보 사고, 혼합 빌드 | 즉시 중단. P0 등록·수정·검증 뒤 새 빌드로 6세션 전부 재실행 |
| `HOLD_INCOMPLETE` | 유효 세션 6명 미만, locale 3+3 미달, 힌트 오염 | 결론·밸런스 변경 보류. 같은 조건의 유효 세션을 보충하되 빌드가 바뀌면 전부 재실행 |
| `UX_FIRST_P1` | G/R1/C1/P1/W1/END/이해도/locale 합격선 중 하나 미달, CAMP_APPROACH 미달, 같은 핵심 막힘 2명 이상 | 발견성·KO/EN 문구·상태 피드백·입력·배치를 P1로 먼저 수정. 경제 수치는 유지하고 새 6세션으로 재검증 |
| `KEEP_V0.2` | 핵심 이정표·언어·이해도 합격, RESCUE 3~4/6 | 현재 수치 유지. 비차단 마찰은 P2로 정리 |
| `OPEN_ONE_AXIS_REVIEW` | 발견성·언어·이해도는 합격했지만 RESCUE 0~2/6 또는 5~6/6, 또는 동일한 가방-신호 경제 원인이 2명 이상에서 재현 | 하나의 수치 가설만 제안해 사용자 검토를 연다. 자동 변경하지 않고 다른 수치 축은 동결 |

우선순위는 다음과 같다.

1. `P0`: 크래시·softlock·진행 손상·입력 상실·개인정보 사고.
2. `P1`: 핵심 이정표/결말/언어 게이트 미달, 기능 의미 역전, 공간형 캠프 또는 장벽·수영 발견성 차단.
3. `P2`: 합격선 안의 비차단 망설임, 코미디 톤·비핵심 문구, RESCUE 5~6/6의 압박 부족 후보.

`OPEN_ONE_AXIS_REVIEW`는 변경 승인이 아니다. 실제 6인 결과, 공통 원인, 기대 효과, 되돌림 조건을 함께 기록한 뒤 별도 결정으로 승인받는다. 가방 용량과 구조 비용처럼 둘 이상의 축을 동시에 조정하지 않는다.

## 12. 실행 후 증거 계약

이 문서 작성 시점에는 외부 플레이테스트 결과가 없다. 실제 실행 뒤에만 다음을 만든다.

- 익명 코호트 요약: `Docs/QA/Results/wave8-first-user-summary-<build>.md`
- P0/P1/P2 공통 원인: 기존 Forge backlog 항목에 증거 경로와 함께 연결
- 원본 수기 기록지: 저장소에 커밋하지 않으며, 프로젝트의 승인된 보관·폐기 절차가 없으면 집계 확인 뒤 폐기

코호트 요약에는 빌드 commit·EXE SHA, 유효/무효 수, 각 게이트의 전체·locale 분포, END 중앙값, RESCUE 분포, Q1~Q5 결과, 공통 원인과 판정만 적는다. 참가자 식별 정보, 음성·영상, 가상 결과, Steam App ID 또는 임의 영문 제목을 포함하지 않는다.

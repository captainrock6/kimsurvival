# 한국어 기본·영어 지원 및 로케일 확장 QA 체크리스트/테스트 계획

- 결정 출처: 메인 디렉터에서 확정된 사용자 결정
- 반영일: 2026-08-22
- 기준 감사: `2a6e9e6` 독립 PC/Steam 준비도 감사
- 현재 상태: **NOT RUN — 기준 커밋에는 로케일 서비스·번역 테이블·선택 저장 경로가 없고 플레이어 노출 문구가 한국어 리터럴로 연결되어 있음**
- 제품 언어 계약: 한국어(`ko`) 기본, 영어(`en`) 지원, 향후 로케일은 데이터 추가로 확장
- 공식 영문 게임 제목: **미정(TBD)**. 임시 영문명은 번역 승인으로 간주하지 않고 데이터 경로·폴백·레이아웃만 검증
- 적용 시점: ko/en 기능이 통합된 첫 검증 가능 커밋부터 필수 게이트로 적용

## 목적과 판정 원칙

한국어와 영어가 같은 게임 상태·입력·화면 구조를 공유하면서 즉시 전환되고, 선택이 재실행 뒤에도 유지되며, 번역 누락이나 포맷 오류가 플레이를 막지 않는지 검증한다. 동시에 세 번째 로케일 추가가 코드 분기 없이 가능한지와 스페인어처럼 영어보다 길고 확장 글리프를 쓰는 언어를 수용할 화면 여백이 있는지 확인한다.

기능 완료는 언어 선택 버튼이나 영어 문자열 일부가 존재한다는 이유만으로 인정하지 않는다. 결정적 검사, 한국어와 영어 각각의 전체 핵심 루프, 1280×800 영어/가짜 장문 로케일 캡처, 실제 키보드·마우스 및 실제 게임패드 설정 조작, Windows 빌드 재실행 뒤 선택 유지가 모두 필요하다. 실제 패드가 없으면 게임패드 실행 항목은 **미검증(UNVERIFIED)**이며 전체 국제화 게이트를 PASS로 판정하지 않는다.

기존 `Artifacts/Verification/**`과 과거 `Artifacts/ParallelQA/**` 결과는 새 국제화 실행의 증거로 재사용하거나 덮어쓰지 않는다. 매 실행은 새 `Artifacts/ParallelQA/<run-id>/localization/**`에 기록한다.

## 기준 커밋 현황과 예상 최초 판정

`2a6e9e6`에는 `com.unity.localization` 또는 동등한 자체 로케일 계층, ko/en 문자열 카탈로그, 활성 로케일 저장, 누락 키 폴백/로그가 없다. 다음은 대표적인 현재 연결 지점이며 전체 목록이 아니다.

- `Assets/_Project/Scripts/Runtime/KimSurvivalPrototype.cs`: 행동 패널, 버튼, HUD, 조작 안내, 월드 라벨 문자열을 직접 생성
- `Assets/_Project/Scripts/Runtime/GameSession.cs`: 독백, 오류, 획득, 연구, 제작, 귀환, 결과 메시지를 한국어 리터럴 또는 한국어 조사 결합으로 생성
- `Assets/_Project/Scripts/Editor/PrototypeProjectBuilder.cs`와 `ProjectSettings/ProjectSettings.asset`: 제품명을 한국어로 직접 지정
- `Packages/manifest.json`: Unity Localization 패키지 없음

따라서 기준 커밋에서 아래 신규 항목은 실행 PASS가 아니라 **NOT RUN / 미구현**이다. 구현 후 최초 하드코딩 검사는 허용 목록에 없는 플레이어 노출 리터럴 때문에 FAIL이 예상되며, 런타임 수정은 이 문서 작업의 범위가 아니다.

## 로케일 아키텍처 수용 계약

구현 방식은 Unity Localization 또는 동등한 자체 계층 중 하나를 선택할 수 있지만 다음 외부 동작은 같아야 한다.

1. 로케일 레지스트리는 `ko`, `en`, 비출하 테스트 로케일을 데이터로 선언한다. 새 언어는 테이블·폰트 메타데이터 추가만으로 등록되고 화면별 코드 수정이나 `if (locale == "en")` 분기를 요구하지 않는다.
2. 모든 플레이어 노출 문구는 안정된 키로 조회한다. 코드와 씬은 번역 원문이 아니라 키와 포맷 인수를 전달한다.
3. 첫 실행 또는 저장값 부재 시 `ko`가 선택된다. 알 수 없거나 손상된 저장값도 `ko`로 복구하고 구조화된 경고를 남긴다.
4. 활성 로케일 변경 이벤트는 현재 열린 HUD·패널·월드 라벨과 이후 생성되는 UI/월드 텍스트 모두에 적용된다. 씬 재로드는 필요하지 않으며 게임 상태·포커스·선택·자원은 바뀌지 않는다.
5. 요청 로케일에 키가 없으면 `ko` 문자열로 폴백한다. 빈 문자열, 원시 키, 예외로 대체하지 않는다.
6. 누락 로그는 최소 `key`, `requestedLocale`, `fallbackLocale`, `surface/context`를 포함하고 같은 키/맥락은 실행 중 한 번만 기록해 로그 폭주를 막는다.
7. 포맷 키는 로케일 간 변수 이름·타입이 일치한다. 번역자가 변수 토큰을 이동할 수는 있지만 삭제·변경할 수 없다.
8. 수량 규칙은 로케일별로 처리한다. 영어의 단수/복수와 한국어의 자연스러운 수량 표기가 숫자 0, 1, 2, 큰 수에서 깨지지 않는다.
9. 폰트 및 폴백 체인은 한글, 기본 라틴, 숫자, 문장부호와 테스트용 스페인어 확장 글리프를 포함한다. 누락 글리프는 자동 검사와 캡처에서 모두 0이어야 한다.
10. 언어 설정은 키보드·마우스와 게임패드가 같은 설정 모델을 조작한다. 장치별로 다른 저장 키나 별도 언어 상태를 만들지 않는다.
11. 공식 영문 제목은 승인 전까지 `TBD` 상태를 유지한다. 임시 표기는 로컬라이즈된 데이터 항목으로만 두고 코드·빌드 스크립트에 최종 명칭처럼 하드코딩하지 않는다.

## 핵심 불변 조건

각 전환/재실행 테스트는 다음 스냅샷을 행동 전후에 남긴다.

- `activeLocale`, `savedLocale`, `availableLocales`
- 현재 phase/day, 플레이어 위치, 체력·허기·일광
- 자원·가방·도구·연구·설비·구조 신호 상태
- 현재 선택/포커스와 열린 패널
- 화면에 표시된 localization key, 해석된 문자열, 포맷 인수
- 누락 키·누락 글리프·포맷 오류 로그 수
- 마지막 입력 장치와 언어 설정 조작 경로

필수 불변식:

1. `ko → en → ko` 전환 중 게임플레이 상태와 자원은 변하지 않고 표시 문자열만 갱신된다.
2. `en` 저장 후 정상 종료·재실행하면 첫 화면부터 `en`이며 한국어가 잠깐 노출되는 플래시가 없다.
3. 저장값 삭제 시 다음 실행은 `ko`; 유효하지 않은 저장값은 `ko`와 경고 1건으로 복구된다.
4. 누락된 `en` 키는 같은 키의 한국어로 표시되고 원시 키·빈칸·예외가 나타나지 않는다.
5. 포맷 뒤 `{name}`, `{count}` 같은 원시 토큰이 화면이나 로그에 남지 않는다.
6. 로케일 전환은 버튼 포커스, 설정 선택, 게임 일시정지 상태를 잃지 않는다.
7. 언어에 따라 핵심 루프의 버튼 활성 조건, 비용, 판정, 보상, 실패 이유가 달라지지 않는다.
8. 이후 생성되는 팝업·월드 라벨도 현재 활성 로케일을 즉시 사용한다.

## 테스트 데이터와 픽스처

### 필수 로케일

| ID | 용도 | 출하 여부 | 규칙 |
|---|---|---:|---|
| `ko` | 기본/최종 폴백 | 예 | 모든 필수 키와 한글 폰트 커버리지 보유 |
| `en` | 지원 언어 | 예 | `ko`와 키·포맷 변수 집합 일치 |
| `qps-long` | 장문/확장 글리프 스트레스 | 아니요 | 영문 기준 길이 35~50% 확장, `⟦…⟧` 래핑, 변수 토큰 보존 |

`qps-long`은 번역 품질을 평가하지 않는다. 영문 문자열을 결정적으로 확장하고 `á é í ó ú ü ñ ¿ ¡` 같은 스페인어 대응 글리프를 섞되 숫자·리치텍스트 태그·포맷 변수는 변형하지 않는다. 이 로케일이 제품 빌드의 일반 언어 목록에 노출되면 P2다.

### 포맷/수량 대표 키

최소 다음 의미를 갖는 키를 고정 픽스처로 제공한다. 실제 키 이름은 구현을 따르되 의미와 경계값을 유지한다.

- 자원 획득: 자원명과 수량 `{resource}`, `{count}`
- 가방: 사용 슬롯/총 슬롯 `{used}`, `{capacity}`
- 비용: 자원별 필요량과 보유량 `{required}`, `{owned}`
- 날짜/일광: `{day}`, `{remaining}`
- 구조 신호: `{current}`, `{total}`
- 누락 테스트: `qa.missing.en.only`는 `ko`에만 존재하고 `en`에서는 의도적으로 누락
- 수량 경계: 0, 1, 2, 9999

### 하드코딩 문자열 스캔 계약

단순 한글 정규식만으로는 영어 UI 리터럴을 찾을 수 없으므로 최종 자동 검사는 문자열이 플레이어 노출 sink로 흐르는지를 분석해야 한다.

필수 검사 대상:

- C# 문자열 리터럴이 `TMP_Text.text`, `Text.text`, 버튼/라벨/툴팁/대화 생성 함수로 전달되는 경로
- `CreateText`, `CreateButton`, `CreateWorldLabel`과 동등한 UI/월드 텍스트 헬퍼 인수
- `LastMessage`, 결과 이유, 자원/도구/설비 표시명, 입력 안내처럼 UI가 소비하는 모델 문자열
- 씬/프리팹/ScriptableObject의 `m_Text`와 플레이어 노출 serialized string
- 설정, 오류, 확인 창, 로딩, 결과, 제품 내 제목과 접근성 안내
- 한국어·영어 모두. ASCII 정규식만으로 영어를 판별하지 않고 문법 트리와 sink 흐름을 함께 사용

승인된 제외는 별도 allowlist 한 곳에서만 관리한다. 각 항목은 `id`, `file`, `line 또는 literal hash`, `category`, `reason`, `owner`, `expires`를 가져야 한다. 허용 category는 승인된 디버그 로그, assertion/테스트 보고, 내부 오브젝트 이름, 자산 ID로 제한한다. `Debug.Log`라는 이유만으로 자동 제외하지 않으며, 플레이어에게 보이는 디버그 문구는 제외할 수 없다.

초기 현황을 빠르게 확인하는 보조 명령은 다음과 같다. 이 명령의 0건만으로 LOC-E16을 PASS 처리하지 않는다.

```powershell
rg -n '[가-힣]' Assets/_Project/Scripts/Runtime -g '*.cs'
```

스캐너 출력은 최소 `file`, `line`, `literal`, `sink`, `localeRisk`, `allowlistId`를 포함하는 JSON과 사람이 읽는 요약을 함께 남긴다. 허용되지 않은 플레이어 노출 리터럴 1건 이상이면 release gate는 FAIL이다.

## 1280×800 가독성 및 장문 로케일 계획

각 캡처는 Windows Player 1280×800, UI 스케일 100%, 동일한 카메라/게임 상태로 생성한다. 원본 PNG를 1:1로 확인하고 OCR만으로 판정하지 않는다. 기존 감사의 P1 월드 상호작용 라벨 결함이 해결되지 않았다면 영어/가짜 로케일 화면도 PASS로 승격하지 않는다.

## 수동 체크리스트

- [ ] 새 설치/저장값 없음에서 한국어가 기본이다.
- [ ] ko/en 전환이 씬 재로드 없이 현재 열린 UI·HUD·월드 라벨에 즉시 반영된다.
- [ ] 영어 선택 후 Windows Player를 종료하고 재실행해도 선택이 유지된다.
- [ ] 저장값 삭제와 잘못된 로케일 값에서 한국어로 안전하게 복구된다.
- [ ] 누락된 영어 번역은 한국어로 표시되고 키·빈칸·예외가 보이지 않는다.
- [ ] 누락 로그에 키/요청 로케일/폴백 로케일/화면 맥락이 있고 반복 폭주하지 않는다.

- [ ] 0/1/2/9999 수량과 영어 단수·복수, 한국어 수량 표시가 자연스럽다.
- [ ] 한글·라틴·숫자·문장부호·스페인어 대응 확장 글리프가 모두 렌더된다.
- [ ] 1280×800 영어의 캠프, 수색/수영, 가방, 설정, 결과 화면에 잘림·겹침이 없다.
- [ ] `qps-long` 35~50% 확장 화면이 1280×800에서 핵심 조작과 수치를 가리지 않는다.
- [ ] 키보드·마우스로 언어 설정의 진입, 선택, 적용, 취소가 가능하다.
- [ ] 실제 게임패드로 같은 설정 조작이 가능하고 포커스가 유지된다.

- [ ] 영어로 같은 전체 핵심 성공 루프를 완주했다.
- [ ] ko/en 각각에서 실패 결과와 재시작 경로를 확인했다.
- [ ] 승인된 디버그 allowlist 밖의 플레이어 노출 한국어·영어 하드코딩 문자열이 0건이다.
- [ ] 새 테스트 로케일을 데이터 추가만으로 등록하고 화면 코드 변경이 없음을 확인했다.
- [ ] 공식 영문 게임 제목은 `TBD`로 기록되고 임시명이 최종 승인으로 보고되지 않는다.

## 심각도와 결함 기록

- **P0**: 로케일 전환/재실행이 크래시·저장 손상·진행 불가능을 일으킴
- **P1**: 선택 미유지, 잘못된 기본 언어, 폴백 실패/원시 키/빈칸, 포맷 예외, 한 언어 또는 한 입력에서 핵심 루프 불가, 허용되지 않은 플레이어 노출 하드코딩 문자열
- **P2**: 1280×800 잘림·겹침, 누락 글리프, 잘못된 복수/수량, 누락 로그 폭주, 가짜 장문 로케일 실패, 포커스/입력 안내 불일치
- **P3**: 의미나 조작을 막지 않는 경미한 문장부호·띄어쓰기·어조 불일치

각 결함은 `ID / P0~P3 / 커밋 / Unity 버전 / 로케일 / 입력 장치 / 해상도 / 재현 단계 / 예상 / 실제 / 영향 / 권장 수정 파일 / 증거`를 기록한다. 공식 영문 제목의 문구 승인 미정 자체는 결함이 아니지만, 최종 승인된 것처럼 하드코딩·표시·보고하면 P2다.

## 최종 완료 게이트

국제화 준비도 PASS는 다음을 모두 만족할 때만 허용한다.

1. Unity 컴파일과 LOC-E01~E20이 새 실행에서 PASS한다.
2. 한국어와 영어 각각 성공 전체 루프와 실패/재시작 경로를 완주한다.
3. 실제 키보드·마우스와 실제 게임패드로 언어 설정을 조작하고, 실제 게임패드만으로 ko/en 핵심 루프를 완주한다.
4. Windows 개발 빌드에서 `en` 선택을 저장하고 프로세스 재실행 뒤 유지한다.
5. LOC-U01~U08의 1280×800 영어/가짜 장문 로케일 화면이 모두 PASS한다.
6. 의도적 누락 픽스처를 제외한 누락 키, 원시 포맷 토큰, 누락 글리프가 0건이다.
7. 승인된 allowlist 밖의 플레이어 노출 한·영 하드코딩 문자열이 0건이다.
8. 새 로케일을 데이터 추가만으로 등록할 수 있고 런타임·화면별 코드 분기가 없다.
9. 국제화 관련 P0/P1가 0건이고 기존 핵심 루프·수영·가방·건설·제한적 배치 회귀가 없다.
10. 공식 영문 게임 제목은 승인 전까지 `TBD`로 명시한다. 문구의 최종 승인 여부는 이 기능 게이트와 별개지만 데이터 기반 제목 경로와 레이아웃은 검증한다.

하나라도 실행하지 못하면 해당 항목은 PASS가 아니라 **미검증**이며 전체 판정에 그대로 반영한다.

# 베이스캠프 제한적 자유 배치 QA 체크리스트 및 테스트 계획

- 결정 출처: 메인 디렉터에서 확정된 사용자 결정
- 반영일: 2026-08-22
- 기준 감사: `2a6e9e6` 독립 PC/Steam 준비도 감사
- 현재 상태: **NOT RUN — 기준 커밋에는 배치/재배치 시스템이 구현되어 있지 않음**
- 적용 시점: 베이스캠프 제한적 자유 배치 기능이 통합된 첫 검증 가능 커밋부터 필수 게이트로 적용

## 목적과 판정 원칙

플레이어가 베이스캠프의 일반 설비를 정해진 안전 구역 안에서 배치·재배치할 수 있고, 구조 신호대 같은 특수 설비는 전용 앵커에만 배치되며, 어떤 입력 장치를 사용하더라도 자원·인스턴스·이동 통로·상호작용 접근성이 보존되는지 검증한다.

기능 완료는 파일이나 UI가 존재한다는 이유만으로 인정하지 않는다. 결정적 규칙 검사, Play Mode 전체 행동 경로, 1280×800 캡처, 실제 키보드·마우스와 실제 게임패드 실행 증거가 모두 필요하다.

## 범위

### 포함

- 일반 설비 최소 2종의 유효 위치 신규 배치와 재배치
- 특수 설비의 전용 앵커 제한
- 배치 유령의 유효/무효 피드백
- 캠프 배치 경계 밖 배치 거부
- 기존 설비와 겹치는 배치 거부
- 출입구와 필수 이동 통로를 차단하는 배치 거부
- 취소 시 자원·설비 수·설비 위치 불변
- 신규 건설 성공 시 비용 정확히 1회 차감
- 재배치 시 추가 비용 차감, 인스턴스 복제, 기능 중복 없음
- 배치 후 플레이어가 상호작용 지점에 접근하고 설비 기능을 사용할 수 있음
- 키보드·마우스와 게임패드의 동등한 배치/재배치 조작
- 1280×800에서 유령 상태, 비용, 확인/취소, 오류 원인의 가독성

### 제외

- 완전 자유 회전 또는 임의 각도 회전
- 물리 기반 적층, 낙하, 기울기 시뮬레이션
- 복층·다층 건축과 층간 경로 탐색
- 장식물 대량 배치, 건축 그리드 편집기, 청사진 저장
- Steam Workshop, 온라인 공유, 멀티플레이 동기화

제외 항목이 동작하지 않는 것은 결함으로 기록하지 않는다. 다만 제외 기능처럼 보이는 UI나 안내가 노출되어 플레이어를 오도하면 P2 사용성 결함으로 기록한다.

## 설비 분류와 테스트 픽스처

현재 모델을 기준으로 다음 대표 설비를 사용한다. 실제 구현의 데이터 자산이나 정책 테이블이 최종 권위이며, 이름이 바뀌어도 동일 역할의 설비로 치환한다.

| 분류 | 대표 설비 | 필수 검증 |
|---|---|---|
| 일반 G1 | 모닥불 | 유효 위치 A 배치, 유효 위치 B 재배치, 겹침/경계/통로 거부 |
| 일반 G2 | 작업대 | 유효 위치 B 배치, 유효 위치 C 재배치, G1과 겹침 거부, 상호작용 접근 |
| 일반 선택 | 빗물받이 | 구현 범위에 포함되면 G1/G2와 같은 규칙 회귀 검증 |
| 특수 S1 | 구조 신호대 | 지정 앵커 배치만 허용, 앵커 밖·다른 앵커 거부, 단계 업그레이드 후 위치/인스턴스 보존 |

검증 가능한 QA 씬 또는 데이터 픽스처는 다음 지점을 안정적으로 제공해야 한다.

- `VALID-A`, `VALID-B`, `VALID-C`: 일반 설비를 둘 수 있고 통로를 막지 않는 서로 다른 유효 위치
- `OUTSIDE-1`: 캠프 배치 경계를 완전히 벗어난 위치
- `OVERLAP-G1`: 이미 놓인 G1의 점유 영역과 겹치는 위치
- `ENTRANCE-BLOCK`: 캠프 출입구의 예약 영역을 침범하는 위치
- `CORRIDOR-BLOCK`: 플레이어 시작점에서 출입구/필수 설비로 이어지는 필수 이동 통로를 차단하는 위치
- `SPECIAL-ANCHOR-1`: S1에 허용된 전용 앵커
- `SPECIAL-OFF-ANCHOR`: 일반 배치 구역 안이지만 S1 전용 앵커가 아닌 위치
- `INTERACT-APPROACH`: 배치 후 설비 상호작용 반경에 도달 가능한 플레이어 경로

경계·점유 영역·예약 통로·전용 앵커는 화면상의 장식 위치가 아니라 런타임이 판정에 사용하는 동일 데이터를 QA가 읽어야 한다.

## 입력 동등성 계약

| 행동 | 키보드·마우스 | 게임패드 | 동등성 기준 |
|---|---|---|---|
| 배치 모드 진입 | 캠프 설비 버튼 클릭 또는 키보드 선택/확인 | 방향 입력으로 설비 선택 후 확인 | 같은 설비·비용·초기 유령 상태 |
| 유령 이동 | 마우스 포인터 또는 이동 키 | 왼쪽 스틱과 지원 대상 D-pad | 같은 스냅/경계/유효성 판정 |
| 배치 확정 | 클릭 또는 확인 키 | A/Submit | 정확히 한 인스턴스 생성, 비용 1회 차감 |
| 취소 | 우클릭 또는 Esc/취소 키 | B/Cancel | 상태와 자원 완전 복원 |
| 재배치 시작 | 기존 설비 선택 후 재배치 | 동일 설비 포커스 후 재배치 | 기존 인스턴스 ID 유지, 추가 비용 없음 |
| 무효 위치 확인 | 확정 입력 시도 | A/Submit 시도 | 배치되지 않고 같은 거부 사유 표시 |

실제 바인딩 이름은 구현을 따른다. 최종 PASS에는 합성 EventSystem 호출만으로 부족하며 실제 키보드·마우스와 실제 게임패드 각각의 실행 로그 또는 영상/캡처가 필요하다. D-pad를 지원한다고 안내한다면 전용 축/액션과 실기 결과가 있어야 한다.

## 핵심 불변 조건

각 테스트는 행동 전후 스냅샷을 남긴다.

- `resourceBefore`, `resourceAfter`: 자원 종류별 정수 수량
- `structureCountBefore`, `structureCountAfter`: 설비 종류별 인스턴스 수
- `instanceIdBefore`, `instanceIdAfter`: 재배치 대상의 안정 인스턴스 ID
- `positionBefore`, `positionAfter`: 배치 좌표 또는 앵커 ID
- `interactionCountBefore`, `interactionCountAfter`: 기능 구독/상호작용 대상 수
- `placementState`: Idle, PreviewValid, PreviewInvalid, Confirmed, Cancelled 중 하나

필수 불변식:

1. 취소: 모든 자원, 설비 수, 인스턴스 ID, 위치가 행동 전과 같다.
2. 신규 건설: 비용만 정확히 1회 차감되고 해당 종류 인스턴스 수가 정확히 1 증가한다.
3. 무효 확정: 자원·설비 수·위치가 변하지 않는다.
4. 재배치: 자원 변화 0, 설비 수 변화 0, 인스턴스 ID 변화 0, 위치만 유효 위치로 바뀐다.
5. 반복 확인/키 리피트: 한 번의 의도에 두 번 차감하거나 두 인스턴스를 만들지 않는다.
6. 특수 설비: 허용 앵커 ID 외 위치에서는 절대 Confirmed가 되지 않는다.
7. 접근성: 배치 후 플레이어가 유효 이동 경로로 상호작용 반경까지 도달할 수 있다.

## 수동 탐색 체크리스트

- [ ] G1과 G2를 서로 다른 유효 위치에 배치할 수 있다.
- [ ] G1과 G2를 각각 한 번 이상 다른 유효 위치로 재배치할 수 있다.
- [ ] S1은 전용 앵커에만 놓인다.
- [ ] 유효/무효 유령이 움직이는 동안 즉시 구분된다.
- [ ] 경계 밖 배치가 거부된다.
- [ ] 설비 겹침이 거부된다.
- [ ] 출입구 침범이 거부된다.
- [ ] 필수 이동 통로 차단이 거부된다.
- [ ] 취소 전후 자원 수량이 같다.
- [ ] 신규 건설 비용이 정확히 한 번만 빠진다.
- [ ] 재배치 비용이 추가로 빠지지 않는다.
- [ ] 재배치 후 설비 수와 인스턴스 ID가 같다.
- [ ] 빠른 연속 확인으로 설비가 복제되지 않는다.
- [ ] 배치 후 플레이어가 설비까지 이동할 수 있다.
- [ ] 배치 후 상호작용 프롬프트와 기능이 정상이다.
- [ ] 키보드·마우스로 전체 경로를 완료한다.
- [ ] 실제 게임패드로 같은 전체 경로를 완료한다.
- [ ] 1280×800에서 비용·상태·거부 사유·조작 안내를 읽을 수 있다.
- [ ] 완전 자유 회전·물리 적층·복층 건축이 없어도 현재 범위 결함으로 기록하지 않는다.

## 심각도 기준

- **P0:** 크래시, 저장/런 상태 파괴, 무한 자원·무제한 설비 복제처럼 테스트를 계속할 수 없는 문제
- **P1:** 무효 위치 허용, 자원 이중 차감, 재배치 복제, 특수 앵커 우회, 출입구/필수 통로 봉쇄, 배치 후 상호작용 불가, 한 입력 방식으로 완료 불가
- **P2:** 유령 상태/거부 이유 불명확, 입력 장치 간 피드백 차이, 1280×800 일부 안내 잘림, 장치 전환 상태 손실
- **P3:** 기능에는 영향이 없는 짧은 깜박임, 미세 정렬, 비핵심 문구 불일치

## 실행 순서와 증거 규칙

1. Unity 컴파일을 수행하고 배치 관련 오류·경고 수를 기록한다.
2. BCP-E01–E14 결정적 Edit Check를 실행한다.
3. `KimSurvivalPrototype` 시작 씬 또는 배치 전용 QA 씬에서 BCP-P01–P10을 실행한다.
4. 키보드·마우스와 실제 게임패드를 별도 실행으로 기록한다.
5. BCP-U01–U05를 1280×800 고정 렌더 타깃과 Windows 플레이어에서 캡처한다.
6. Windows x64 Development Build를 생성하고 배치·재배치 스모크를 실행한다.
7. 결과를 P0–P3, 재현 단계, 영향, 권장 수정 파일로 보고한다.

기존 `Artifacts/Verification`은 사용하거나 덮어쓰지 않는다. 권장 새 증거 구조:

```text
Artifacts/ParallelQA/<run-id>/placement/
  compile-result.txt
  edit-checks.txt
  playmode-keyboard-mouse.txt
  playmode-gamepad.txt
  placement-valid-1280x800.png
  placement-invalid-boundary-1280x800.png
  placement-invalid-overlap-1280x800.png
  placement-invalid-corridor-1280x800.png
  placement-special-anchor-1280x800.png
  windows-development-build.txt
  placement-qa-report.md
```

각 결과에는 기준 커밋, Unity 버전, UTC 시작/종료 시각, 정확한 실행 명령, 입력 장치 이름, 테스트 ID, PASS/FAIL/UNVERIFIED를 기록한다. 실제 게임패드가 없으면 BCP-P09와 게임패드 실행 행은 PASS가 아니라 **UNVERIFIED**로 남긴다.
